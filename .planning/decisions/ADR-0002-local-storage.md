# ADR-0002: 데이터 저장 방식 선택

- 상태: Accepted
- 날짜: 2026-05-18
- 결정자: 원동현

## 배경

운동 기록(세션, 세트, 종목, 무게, 횟수)을 어디에 어떻게 저장할지 결정이 필요하다. 클라우드 동기화가 필요한지, 로컬만으로 충분한지도 포함.

## 고려한 대안

### 대안 A: SQLite (expo-sqlite)
- 장점: 구조화된 쿼리, 관계형 데이터에 적합, 무료 티어 없음
- 단점: 기기 간 동기화 불가, 스키마 변경 시 마이그레이션 필요

### 대안 B: Firebase Firestore
- 장점: 클라우드 동기화, 실시간 업데이트
- 단점: 무료 티어 한도, 네트워크 의존성, 설정 복잡

### 대안 C: Hive (NoSQL 로컬)
- 장점: 빠른 키-값 저장, 설정 간단
- 단점: 복잡한 쿼리 불가, 운동 기록처럼 관계형 데이터에 부적합

### 대안 D: SharedPreferences
- 장점: 초간단 설정
- 단점: 단순 키-값만 가능, 운동 기록 저장에 부적합

## 결정

**SQLite (expo-sqlite 패키지)**를 선택한다.

## 이유

- 운동 기록은 세션-세트-종목의 관계형 구조 → 관계형 DB가 적합
- 백엔드 없이 완결되어 무료 티어 의존 위험 없음 (위험 #1 예방)
- Won't에서 클라우드 동기화를 명시적으로 제외했으므로 Firebase 불필요
- React Native (Expo)에서 expo-sqlite는 별도 설치 없이 기본 제공

## 결과

긍정:
- 오프라인 완전 동작 — 발표 데모 시 Wi-Fi 의존 없음
- API 비용 없음

부정 / 제약:
- 기기 간 데이터 이전 불가 (개발 단계에선 무관)
- 스키마 변경 시 마이그레이션 코드 직접 작성 필요
